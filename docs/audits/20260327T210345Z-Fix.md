## ✅ RF2-1 — Synthesis blocked trotz P0-Fix

**Severity:** kritisch  
**Status:** ✅ Erledigt

**Umsetzung:**
- `supervisor_loop.py`: Synthesis-Envelope Keys von `raw_synthesis`/`admitted_synthesis` auf `raw_package`/`admitted_payload` geaendert
- `envelope.py`: `is_envelope()` akzeptiert jetzt auch `raw_synthesis` als Legacy-Key fuer Altartefakte
- `envelope.py`: `resolve_raw_package()` faellt auf `raw_synthesis` zurueck wenn `raw_package` fehlt
- `follow_up.py`: `_synthesis_answer` liest jetzt ueber `resolve_raw_package()` statt direkt aus Envelope-Root
- `tests/architecture/test_envelope.py`: 8 neue Regressionstests fuer Synthesis-Envelope (kanonisch + Legacy)

### Diagnose (aus chat_history.json)

Die Synthesis-GroupChat hat **korrekt funktioniert**:

1. `read_report_segment` hat alle 4 Department-Segmente erfolgreich gelesen (P0-Fix wirkt)
2. SynthesisAnalyst hat eine vollstaendige Cross-Domain-Analyse geschrieben
3. SynthesisCritic hat **APPROVED**
4. SynthesisLead hat `finalize_synthesis` aufgerufen → `SYNTHESIS_READY\nTERMINATE`
5. Supervisor hat **`"decision": "accepted"`** zurueckgegeben

Das Problem liegt **nach** der GroupChat, in der Envelope-Lesung durch `pipeline_runner.py`.

### Root Cause (bewiesen)

Der Synthesis-Envelope in `supervisor_loop.py` (Zeile ~340) wird mit einem **abweichenden Key** gebaut:

```python
synthesis_envelope = {
    "admission": { ... },
    "raw_synthesis": synthesis_result,   # ← NICHT "raw_package"
}
```

Aber `is_envelope()` in `envelope.py` prueft:

```python
def is_envelope(pkg):
    return "admission" in pkg and "raw_package" in pkg  # ← erwartet "raw_package"
```

Der Synthesis-Envelope hat `raw_synthesis`, nicht `raw_package`. Daher:
- `is_envelope()` → `False`
- `resolve_admission()` → Fallback `{"decision": "unknown"}`
- `pipeline_runner.py` liest `synthesis_admission = "unknown"`
- `"unknown" != "accepted"` und `!= "accepted_with_gaps"` → **blocked-Pfad**

Die Supervisor-Entscheidung `"accepted"` wird korrekt in den Envelope geschrieben, aber `pipeline_runner.py` kann sie nicht lesen weil der Envelope nicht als solcher erkannt wird.

### Patch-Sequenz

**Option A (minimal, empfohlen):** `envelope.py` / `is_envelope()` erweitern:
- Auch `raw_synthesis` als Envelope-Indikator akzeptieren
- Oder: `is_envelope()` prueft nur auf `"admission"` (das ist der eigentliche Indikator)

**Option B (sauberer):** `supervisor_loop.py` / Synthesis-Envelope auf `raw_package` umstellen:
- `"raw_synthesis"` → `"raw_package"` und `"admitted_synthesis"` → `"admitted_payload"`
- Damit ist der Synthesis-Envelope identisch zum Department-Envelope

**Empfehlung:** Option B — eine Shape fuer alle Envelopes.

## ✅ RF2-2 — `employees` bleibt n/v

**Severity:** niedrig-mittel  
**Status:** ✅ Erledigt

**Umsetzung:**
- `worker.py`: RF-5 Bridge erweitert — sucht jetzt auch in `synthesis.facts` (nicht nur `recent_events`)
- `worker.py`: 4 Regex-Patterns statt 1: `approximately N employees`, `N employees`, `workforce of N`, `N Mitarbeiter`

### Finding

Der RF-5 Regex `([\d.,]+)\s*(?:to\s*[\d.,]+\s*)?employees` hat keinen Match in den `recent_events` gefunden. Die Events enthalten:
- "workforce reductions" (kein absoluter Wert)
- "Planned workforce reduction of approximately 11,000 to 14,000 employees" — dieser Text stand im vorherigen Run, aber nicht in diesem

Der aktuelle Run hat andere `recent_events`:
- "July 2024: Announced comprehensive realignment of structures including workforce reductions and strategic focus on key divisions"
- Keine absolute Mitarbeiterzahl

### Root Cause

1. Die `recent_events` im neuen Run enthalten keine absolute Mitarbeiterzahl — nur "workforce reductions" ohne Zahl
2. Der RF-5 Regex ist zu eng: er sucht nur in `recent_events`, nicht in `facts` oder `page_evidence`
3. Wikipedia und andere Quellen enthalten die Zahl (~165.000 Mitarbeiter), aber der LLM hat sie nicht in `recent_events` geschrieben

### Patch-Sequenz

1. **`worker.py` / RF-5 Bridge erweitern:** Zusaetzlich zu `recent_events` auch in `synthesis.facts` und `evidence_pack.page_evidence` nach Mitarbeiterzahlen suchen
2. **Regex erweitern:** Auch Patterns wie `approximately [\d.,]+ employees`, `workforce of [\d.,]+`, `[\d.,]+ Mitarbeiter` matchen
3. **LLM-Prompt fuer `company_fundamentals` verschaerfen:** Explizit nach Mitarbeiterzahl fragen, auch wenn sie nicht auf der Homepage steht (Wikipedia, Annual Report)

### Akzeptanzkriterien

- `employees` ist nicht `n/v` wenn irgendeine Quelle im Run eine Mitarbeiterzahl enthaelt
